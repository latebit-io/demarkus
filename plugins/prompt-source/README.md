# prompt-source

Canonical prompt templates for the demarkus agent plugins.

The runtime prompt files shipped by the seven agent plugins (claude-code, claude-code-knowledge, opencode-memory, opencode-knowledge, pi-memory, pi-knowledge, cursor-memory) are generated from the templates here. `memory/` and `knowledge/` hold the `commands/`, `context/`, and `skills/` template trees; `manifest.json` maps each template to its per-surface output targets.

## Workflow

Edit the templates here, never the generated files, then regenerate:

```bash
cd tools && go run ./plugin-prompts write
```

Verify without writing:

```bash
cd tools && go run ./plugin-prompts check
```

A `commands/<old>.md.alias` file whose body names another command renders that command's full body under the old name with a `Deprecated alias of /<new>` description prefix, so a renamed command keeps working under both names on every harness while the alias file exists.

## Store noun

Prose never calls the personal store "memory": hosts ship a built-in memory feature and agents conflated the two. Templates write `{{.Store}}`, `{{.Stores}}`, and `{{.StoreTitle}}` (default `soul` / `souls` / `Soul`); a target or brand overrides them with `store_noun` and `store_noun_plural` in `manifest.json`. Plugin names, MCP server ids, and registry subcommands are identifiers and stay as they are; slash commands follow the noun (`/soul-*`).

## Brands

A `brands` entry in `manifest.json` renders a Claude Code base target under another plugin name into `plugins/brands/<name>/`. This repository ships no brands; a fork adds its own. See [plugins/brands/README.md](../brands/README.md) for the rebranding guide.

Generated files carry a `Code generated by tools/plugin-prompts; DO NOT EDIT` marker. CI and pre-commit run the `check` mode and reject drift between templates and generated artifacts.

## Token budget

Every byte here is paid in tokens: session guidance on every session, command and skill bodies on every invocation, and MCP tool descriptions (in `client/cmd/demarkus-mcp` and `tools/internal/broker/mcp_tools_list.go`) on every request in hosts that eager-load schemas. Rules for any edit:

- Terse prose. Fragments, no articles or filler, no rationale a step already implies. Rationale belongs in the soul, not the prompt.
- Behavior first. Keep every step, rule, path, flag, shell snippet, output shape, and template directive. Shorten the words around them.
- Nothing volatile. No timestamps, ids, or counts in guidance, nudges, or descriptions; they break prompt-cache prefixes.
- No em dashes.
- Regenerate and bump the affected plugin lineage in the same PR.
